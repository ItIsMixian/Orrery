# 真实开发上下文路由基准

Status: Approved
Governing ADR: [ADR-0002](../decisions/0002-real-development-benchmark-portfolio.md)
Updated: 2026-08-19

## 目标

用隔离、可复现的小型真实开发任务评价 Agent 的上下文路由，而不是只评价它维护 Project Orrery 文档的能力。代码和可观察行为是主要交付物，Project Orrery 权威链用于判断实现之后是否仍可定位、可解释、可验证。

## 任务组合

任务比例按连续多轮实验的滚动组合衡量，不要求每个三任务 Pilot 精确满足百分比。

| 任务轨 | 目标比例 | 主要交付物 | 典型问题 |
|---|---:|---|---|
| 真实产品开发 | 约 60% | 应用代码与自动化测试 | 小型 Bug、行为闭环、小功能、跨模块重构 |
| 安全／迁移／跨模块 | 约 20% | 安全实现、迁移与失败模式测试 | SQLite 迁移、凭据清理、权限门控、回滚 |
| 文档／发布治理 | 约 20% | 文档、索引、发布配置 | ADR/State 对齐、兼容说明、发布同步 |

三任务 Pilot 至少有两项以可运行代码为主要交付物；纯文档题可以作为第三项或进入更大的滚动语料。

## 单项任务结构

每项任务在运行前冻结以下内容：

1. **隔离基线**：可由固定 Git 提交、脱敏代码切片或注入缺陷生成。
2. **用户目标**：只描述需要实现的行为与边界，不泄露标准补丁。
3. **权威入口**：保留目标项目真实的 Agent 入口、相关 State 与有效 ADR；不人为把所有答案集中到一个 Prompt。
4. **受保护范围**：用户数据、凭据、无关模块、历史 ADR 和预置脏文件的不可触碰条件。
5. **独立 Oracle**：由 Harness 在 Agent 结束后执行，不依赖 Agent 自报。
6. **成本记录**：输入、输出、墙钟、代理正文、读取集合和范围扩张。

## 验收层级

Oracle 按以下顺序判定，前一层失败时不能靠后一层补偿：

1. **行为正确性**：目标功能或 Bug 修复能通过独立测试。
2. **数据与安全**：迁移可重复、旧数据保留、密钥不泄露、失败时保守关闭。
3. **范围完整性**：没有修改受保护或无关文件，预置用户改动保持原样。
4. **事实链同步**：只更新确实受影响的 State、Progress、Validation 或用户文档。
5. **决策克制**：没有在局部修复中机械创建 ADR，也没有在改变长期规则时漏掉 ADR。

措辞、段落顺序、特定函数名和标准补丁相似度不得替代上述行为判断。

## 首批候选任务族

候选题从真实项目模式提炼，但要重新构造 fixture，避免直接暴露历史答案：

- **反馈状态 Bug**：自动过期与用户主动“稍后”必须是不同状态，且不能错误延长冷却。
- **持久化迁移**：为已有 SQLite 数据增加字段或索引，保证旧库升级、重复启动和失败回滚。
- **小功能闭环**：增加一个限时暂停或低风险偏好，从入口、持久化、行为门控到恢复与测试形成闭环。
- **凭据生命周期**：删除 Provider 时清理受保护存储，但不得把秘密写入配置、日志或测试产物。
- **真实编排回归**：重构 Agent loop 时证明 safety gate 仍在完整调用链上，而不只是孤立函数测试通过。
- **延期条件判断**：给出满足或未满足 deferred 触发条件的项目状态，检查 Agent 是否正确实施或克制停止。
- **事实对齐**：代码、State、Handoff 和测试计数出现不同步时，以实现与验证为依据更新当前事实，不改写历史 ADR。

## Fixture 与隐私边界

- 不在 Marglo 或其他来源项目的真实工作树中运行模型。
- 构建 fixture 前记录来源提交；若使用当前工作树，只能复制明确白名单且必须排除未提交文件。
- 删除用户数据目录、数据库真实内容、日志、API Key、钥匙串引用值、缓存、构建产物和本机绝对身份信息。
- Fixture 中如需数据库，只使用人工生成的最小旧版本样本。
- 每次运行创建独立 clone／工作目录；模型运行后封存 R0，不回写源项目。
- 对外发布任务时只包含许可明确、已脱敏且不泄露私人历史的内容。

## Pilot 设计要求

- P、候选策略和 Harness 使用同一 fixture、Oracle、模型、推理强度和执行限制。
- 成对任务尽量并行，网络故障和重试必须显式记录。
- 启动前在真实的嵌套隔离路径上跑 preflight，避免再次出现 Pilot 007 的分支名冲突。
- 自动门至少同时覆盖正确性、装置有效性、必要依赖召回、总 input、output、墙钟和正文读取成本。
- 文档同步得分单独报告，不能把代码失败平均掉。

## 当前实施状态

本 Design 已批准，但真实开发 fixture、任务编号、Oracle 和 Pilot 008 控制包尚未创建。后续开工前需要单独的 Implementation Plan 和用户启动确认。
