# Orrery v0.3.0 Onboarding

Use the published `project-orrery-v0.3.0.zip` only after its checksum and GitHub Release are available. Extract it so the archive root remains `project-orrery/`; the embedded packages are part of the runtime and must stay beside the Skill entry.

## New project

1. Verify the ZIP against `project-orrery-v0.3.0.sha256`.
2. Run `python project-orrery/scripts/install_project_orrery.py --target <project> --title "<title>" --dry-run`.
3. Review every planned create/keep/skip action, then rerun without `--dry-run`.
4. Start the local Observatory with `<project>/Start Orrery.vbs` or `<project>/start-orrery.bat`.

The default scaffold is create-only. Existing author documents are preserved. A new project records Authority Model 1 selection with adoption still pending; copying files does not itself approve ADRs or adopt the model.

## Runtime and network boundary

The scaffold receives an exact allowlisted Core/CLI/Observatory source runtime from the archive, so normal local startup does not require a repository checkout, ambient `PYTHONPATH`, network access, PyPI or preinstalled Orrery packages. Personal Mode is the default and stays zero-network. Team Mode must be enabled explicitly for the project and execution requests still require member-local confirmation.

## Verify the installation

Run `python project-orrery/scripts/validate_installation.py --target <project>`. Keep the extracted release archive and checksum until the installation is accepted; they are the clean rollback source.
