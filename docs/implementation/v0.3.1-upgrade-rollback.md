# Orrery v0.3.1 Upgrade and Rollback

## Upgrade safely

Windows v0.3.0 users should upgrade to v0.3.1 to avoid repeated command-window flashes and duplicate-launch attempts. Verify `project-orrery-v0.3.1.zip` against its accompanying `.sha256` file, then run the installer with `--upgrade-tools --dry-run` before applying the upgrade.

The managed-tool upgrade replaces only allowlisted Orrery files and stores prior bytes under `.project-orrery-backup/<timestamp>/`. It does not blanket-overwrite AGENTS, Seed, State, ADR, Design, Plan, Validation or other author-owned documents.

After upgrading, run the installation validator and start Orrery normally. A second normal launch should reuse the same healthy local runtime.

## Roll back

1. Stop the local Orrery service.
2. Locate the matching timestamp under `.project-orrery-backup/`.
3. Restore only the paths recorded for that upgrade, preserving their relative paths.
4. Reconcile `.project-orrery.json` with the restored managed hashes if the operational backup captured it.
5. Run the validator before restarting.

Rollback does not reverse independently authored project decisions or documentation. If the backup is incomplete, recover from the previously verified v0.3.0 archive rather than mixing unverified runtime files.
