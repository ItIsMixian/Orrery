# Orrery v0.3.0 Upgrade and Rollback

## Upgrade safely

First run the installer with `--dry-run`. Without `--upgrade-tools`, Orrery creates missing files and preserves every differing existing file, including author documents and older managed runtime files. This may intentionally leave a mixed toolchain, which the project manifest reports.

Use `--upgrade-tools` only after review. It may replace only paths declared in the v0.3.0 managed launcher/runtime allowlist, and it copies each replaced file to `.project-orrery-backup/<timestamp>/` first. Author-owned AGENTS, Seed, State, ADR, Design, Plan, Validation and other project documents are never blanket-overwritten.

After upgrading, run the installation validator and open the Unified Observatory locally. Do not delete the backup until both checks are satisfactory.

## Roll back

1. Stop the local Orrery service.
2. Locate the upgrade timestamp under `.project-orrery-backup/`.
3. Restore only the paths recorded for that upgrade, preserving their relative paths.
4. Restore the previous `.project-orrery.json` if it was captured by the operational backup procedure, or reconcile its managed hashes with the restored files.
5. Run the validator again before restarting.

Rollback does not reverse authored project decisions or document changes made independently of the installer. If a backup is incomplete, stop and recover from the previously verified release archive or version control rather than mixing unverified runtime files.
