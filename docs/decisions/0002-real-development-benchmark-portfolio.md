# ADR-0002：上下文路由基准必须包含隔离的真实开发任务

Status: Accepted
Date: 2026-08-19

## Context

Pilot 001–007 建立了可封存运行、独立 Oracle、访问代理和成本统计，但任务组合仍偏向 Project Orrery 自身的文档、安装、发布与实验工具维护。Pilot 007 虽包含代码任务，主要交付物依然属于文档系统基础设施，不能充分代表开发者在真实应用中修复行为、迁移持久化数据、增加小功能或维护跨模块安全边界的日常工作。

如果只在文档治理题上评估上下文策略，实验可能奖励擅长整理 Markdown 的流程，却无法回答该流程是否能帮助 Agent 正确修改产品代码。反过来，只测代码也会遗漏 Project Orrery 的核心价值：实现后是否保持决策、当前事实和验证证据可追溯。

Marglo（早期目录名为 NextStep Seed_2）提供了一个真实、长期演化的参考项目：它同时具有 Agent／Human 双入口、ADR 与 State、SQLite 迁移、用户数据保护、凭据隔离、UI、行为门控、测试债务和发布文档。这些模式可以提炼成隔离任务，但真实工作树、用户数据、凭据和未提交改动不能直接进入实验。

## Decision

1. 后续用于评价或采纳上下文路由策略的基准，必须同时包含“真实应用开发轨”和“文档治理轨”。仅由文档维护题组成的实验不得支持通用开发流程的采纳结论。
2. 以滚动任务组合而非每个小 Pilot 为口径，目标构成为：约 60% 真实产品代码开发，约 20% 安全、迁移或跨模块任务，约 20% 纯文档与发布治理任务。三任务小样本至少包含两项以可运行代码为主要交付物的任务。
3. 真实开发任务的主要验收顺序固定为：可运行行为与测试、数据／安全约束、无关文件保护、必要的 State／Progress 等事实链同步。文档同步不能替代代码正确性。
4. 不要求每项开发任务新增 ADR。局部 Bug 修复、保持行为的重构和补测试通常不产生 ADR；只有任务确实改变长期约束时，才由目标项目自己的规则决定是否新增或修订决策。
5. 所有真实开发任务必须运行在一次性隔离仓库中。Fixture 可以由真实历史提交、经过脱敏的代码切片或明确注入的缺陷生成，但不得读取或复制真实用户数据、API Key、钥匙串、运行缓存、仓库外私密资料或源项目未提交工作。
6. 每项任务在模型运行前冻结独立 Oracle。Oracle 优先判断可观察行为、迁移幂等性、安全失败模式和受保护文件范围；不得以固定措辞、实现顺序或无关格式作为主要正确性条件。
7. Marglo 只作为任务模式和 fixture 设计的参考来源。实验不得在它的真实工作树上执行，也不得把其当前文档中的历史答案直接包装成可泄题的任务。
8. 本决定约束 Project Orrery 的研究和采纳方法，不修改当前发布 Skill，也不表示 Pilot 008 或任何真实开发 fixture 已经实现。

## Reasons

- Project Orrery 的目标是降低真实开发中的失控感；评测对象必须覆盖真实开发，而不能只覆盖 Project Orrery 自己最擅长的文档结构。
- 代码、数据、安全和文档共同出现时，才能观察 Context Manifest 或其他路由策略是否真的召回必要依赖、避免无关读取并维护作者意图。
- 使用脱敏隔离 fixture 可以保留真实复杂度，同时让 Oracle 可重复、保护用户数据并避免污染活跃项目。
- 将文档同步放在代码正确性之后，可以防止 Agent 用“写了很多说明”掩盖未实现或错误实现。

## Consequences

- 后续 Pilot 的准备成本会上升：需要构建可重复 fixture、行为 Oracle、旧数据样本和受保护路径清单。
- 小样本实验必须明确它覆盖了哪些任务轨，不能把三项仓库维护题外推为通用软件开发结论。
- 基准将更容易暴露跨模块依赖召回、迁移安全、范围控制和文档维护成本之间的真实权衡。
- 现有 24 项语料和 Pilot 001–007 继续作为历史证据，不因本决定被重分类或改写。
