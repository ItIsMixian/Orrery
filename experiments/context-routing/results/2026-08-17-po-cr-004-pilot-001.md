# PO-CR-004 pilot 001: A/B/C comparison

> **Date:** 2026-08-17  
> **Status:** apparatus pilot; invalid for an architecture decision  
> **Authority:** research evidence only; this report does not change the released Skill or create an ADR

## Executive conclusion

The three runs produced reviewable artifacts, but this pilot cannot establish that variant A, B, or C is superior. The task required a directly usable public GitHub installation address, while neither the common prompt nor the isolated historical repository contained the public owner/repository identity. Variants B and C also read the currently installed Project Orrery Skill outside the historical snapshot, whereas variant A used the repository snapshot. Those two confounds break the controlled comparison.

All three runs passed syntax and repository tests and changed only `README.md`. None passed strict task acceptance:

- A invented `github.com/openai/project-orrery`, which is not the reference repository.
- B used `<owner>/<repository>`, avoiding fabrication but not producing a directly usable instruction.
- C made the same conservative placeholder choice, but also reported reading `.git/config` outside its initial Manifest without declaring a matching scope expansion.

The pilot is therefore useful as a test of the benchmark apparatus, not as evidence for a routing-policy ADR.

The lower reported read counts for B and C and their refusal to invent a repository owner are promising safety and efficiency signals. They are not causal evidence: the access lists are Agent self-reports, timing/token data are unavailable, and the variants did not receive equivalent external context.

## Evidence boundary

The original access events came from the three Agent reports supplied by the operator. They are recorded with `observed_by: agent` and do not prove what content the model actually received.

The evaluator independently observed only the post-run repository state and validation commands:

- `git diff --check` passed in all three repositories;
- `python -m unittest discover -s tests -v` passed with 3 tests in each repository;
- `git diff --name-only` returned only `README.md` in each repository;
- the resulting README installation text and diff object IDs were captured.

The historical reference changed `README.md` from base `e0680523e4cacde2e8413188e04e801e9c2c1c81` to reference `80b17bec84b763a356f54838771d6a9d91133800`. Its direct installation address identifies `yw9299-stack/project-orrery`, a fact unavailable in the isolated baseline and common prompt.

## Apparatus defects found

1. **Gold information was absent.** The acceptance criterion required the public repository identity, but the experiment denied network access, removed remotes, and did not include that identity in the task packet.
2. **External Skill context was not controlled.** B and C read the currently installed Project Orrery Skill, which may contain information newer than the historical snapshot. A did not receive the same source.
3. **Read provenance remains self-reported.** The benchmark can independently verify writes and command results, but not the original model-facing content reads.
4. **Expansion bookkeeping was ambiguous.** C read `.git/config` outside its initial Manifest without a declared expansion. Metadata queries and content reads need an explicit common rule.
5. **Execution measurements were missing.** Model identifier, start/end time, tokens, permission profile, and provider cost were not captured.

## Required corrections before pilot 002

1. Put every fact required for acceptance in the common task packet, or select a task whose gold facts are present at the baseline commit. For PO-CR-004, include the canonical public repository URL explicitly.
2. Run from a clean profile without a globally installed Project Orrery Skill, or pin and expose the same frozen Skill snapshot to every variant.
3. Freeze the pilot-001 prompts as historical evidence. Create versioned pilot-002 prompts instead of editing the used prompts in place.
4. Require reason-coded expansion before any content read or metadata lookup outside the active Manifest, including `.git/config` and remote queries.
5. Capture model, prompt revision/checksum, permissions, timestamps, tokens, and operator interventions automatically where the harness permits.
6. Keep access claims at `agent` evidence until a host-level harness or controlled file wrapper independently records them.
7. Repeat the pilot before starting the 20–30 task comparison. Do not derive an ADR from pilot 001.
