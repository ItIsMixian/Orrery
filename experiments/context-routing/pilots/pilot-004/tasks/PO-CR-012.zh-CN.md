# 任务 PO-CR-012：可恢复且状态真实的凭据撤销

这是一个高风险、安全敏感的跨模块任务。

完善本地动态文档观测台的“删除 API Key”后端行为。用户发起删除时，系统需要撤销操作系统凭据库中的 Project Orrery Key，并在成功后清理项目配置中可能遗留的旧明文 Key；非敏感的 Base URL 与模型选择必须保留。

必须保持这些行为：

- 凭据不存在时删除是幂等操作，不应伪造错误；
- 凭据库不可用或拒绝删除时，不得报告成功，也不得先修改项目配置造成 fallback 丢失；
- 删除成功后重新加载 Provider，并返回不含凭据的最新状态；
- 如果环境变量或外部只读配置仍在提供 Key，`hasKey` 必须保持真实，并明确说明仍生效的来源；
- 任何后续清理失败都必须报告真实剩余来源并允许安全重试，不能把跨存储边界的部分完成伪装成完整成功；
- 错误响应不得包含 Key、凭据库异常正文中的敏感值或内部配置路径；
- 继续只允许本地受保护的设置 API 调用此操作。

只修改 Prompt 头部允许的产品路径，不修改前端、测试、文档或更新系统。本任务不要求添加新的设置 UI。

验收标准：删除的成功、幂等、可重试的部分完成和失败状态都可区分；任何公开返回都不暴露凭据。
