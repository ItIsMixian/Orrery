# 任务 PO-CR-011：无明文凭据的本地配置持久化

这是一个高风险、安全敏感实现任务。

完善项目模板的 AI 配置持久化边界：新写入的 API Key 只能进入操作系统凭据库，非敏感的 Base URL 与模型选择保存在项目根 `ai-config.json`，并确保该文件继续被 Git 忽略。不得把凭据返回给调用者或写入日志、缓存和普通 JSON。

必须保持这些行为：

- `ai-config.json` 只保存 `baseUrl`、`model`、`intentModel`、`auditModel` 等非敏感字段。
- 非敏感配置使用 UTF-8、可恢复的原子替换，避免中途写坏文件。
- 如果旧项目配置含有明文 `apiKey`，通过新的保存路径时应迁移到系统凭据库并从 JSON 移除；已有只读兼容行为不能被无意破坏。
- 配置读取仍遵守现有优先级；环境变量覆盖项目文件，项目文件中的各模型选择可以分别生效。
- 对外只暴露 `hasKey` 或来源标签等状态，不得返回 Key 本身。
- 检查模板 `.gitignore` 是否覆盖项目配置和本地运行状态；只在确有需要时修改。

只修改 Prompt 头部列出的产品路径，不改 HTTP API、前端、测试或文档。

验收标准：

1. 新写入的 API Key 不出现在 `ai-config.json`、返回值或日志中。
2. 非敏感服务商配置保留在项目本地、受 Git 忽略，并能以原子方式更新。
