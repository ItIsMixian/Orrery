# 任务 PO-CR-010：图形化 AI 服务商设置 API

这是一个高风险、跨模块实现任务。

为项目模板中的本地动态文档观测台增加图形设置面板所需的后端 API，使浏览器能够读取非敏感服务商状态、保存 OpenAI-compatible 服务商与模型配置，并执行一次最小连接测试。只实现后端契约，不修改 HTML／CSS／前端资源。

API 契约：

- `GET /api/ai-config` 返回非敏感状态与配置，例如 `hasKey`、`baseUrl`、`model`、`intentModel`、`auditModel` 和可诊断的服务商状态；绝不返回 API Key。
- `POST /api/ai-config` 接收 JSON，保存非敏感配置，并在请求含新 Key 时交给现有凭据存储边界；响应不得回显 Key。
- `POST /api/ai-config/test` 使用当前表单值或既有凭据构造一次最小 OpenAI-compatible 请求，限制输出规模，并以可安全显示的结果报告成功或失败。
- 继续只监听回环地址，响应禁止缓存敏感状态。对 Base URL、模型名、请求体大小和 JSON 类型做有限输入验证。
- 错误消息必须脱敏；即使服务商异常正文包含本次提交的 Key，也不得把它返回浏览器。
- 本轮只实现连接测试，不真实联网验证。

优先复用现有 `_llm.py` 配置和 Provider 抽象，避免在 HTTP 层另建一套互相漂移的服务商规则。只修改 Prompt 头部列出的产品路径，不改测试、静态页面或其他工具。

验收标准：

1. 浏览器可通过稳定 JSON API 读取并保存非敏感服务商／模型配置。
2. 连接测试使用最小请求，失败可诊断且任何响应都不暴露凭据。
