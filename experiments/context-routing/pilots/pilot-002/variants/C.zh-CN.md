# Variant C：选择性上下文与内容预算

可以先做只返回路径名的枚举。在任何仓库正文进入上下文前，先输出一份简短的 `CONTEXT MANIFEST`：

- 任务分类；
- 对本任务采用“不检索／单文件／多文件”哪一级策略；
- 初始允许读取内容的精确文件列表及理由；
- 初始预算：第一次写入前最多让 2 个不同文件的正文进入上下文；
- 预期写入路径、验证与扩展条件。

优先使用标题定位、只返回文件名的搜索和有行号的局部读取。任何会显示正文的搜索都消耗对应文件的内容预算。实施前输出简短的 `SELECTED EVIDENCE`，只收录与修改直接相关的事实。

需要读取第三个文件、Manifest 外文件或扩大已选片段时，必须先输出：

```text
[SCOPE EXPANSION]
path: <仓库相对路径或局部范围>
reason_code: missing-rule | missing-context | validation-failure | dependency-found
reason: <为什么当前证据不足>
```

外部路径和 Git 元数据不能通过扩展纳入。最终报告必须说明每次扩展是在读取前还是读取后声明；读取后补报属于协议违例。
